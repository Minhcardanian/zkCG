# ZK Compliance Gate

Research prototype in development. Screening is synthetic; this is not a compliance service. The participant and issuer UI is a local prototype; it is not hardened for production.

## Local foundation

Requires Node.js 22 and Docker. Install with `npm ci`, then run `docker compose -p zkcg-local up -d --wait postgres`. In another terminal run `npm run node`; deploy locally using `npm run deploy:local`. Copy `.env.example` to an untracked local environment file and set the deployment's gate address, the disposable local on-chain issuer private key and `ISSUER_WALLET_ADDRESSES`, a comma-separated allowlist of issuer sign-in wallet addresses. Load those variables in the shell and run `npm run server`. In another terminal run `npm run dev`, open the displayed loopback URL, and enter the local gate address. Optionally set the public `VITE_GATE_ADDRESS` before starting Vite to prefill it; the field remains editable. Configure a browser wallet for chain ID 31337 and the local RPC. To give a browser-wallet address 1 local test ETH, run `npm run fund:local -- <wallet-address>` while the local node is running; the command only connects to `127.0.0.1:8545` and checks chain ID 31337. Never use the publicly known local Hardhat keys on a public chain.

Run `npm test` for contract tests (including a real Semaphore proof) and `npm run test:issuer` for API behavior against the local PostgreSQL service. The build and service scripts compile contract artifacts when needed. Browser proof generation downloads Semaphore 4.13.0 artifacts from `snark-artifacts.pse.dev`, verifies their SHA-256 hashes against the checked-in manifest and caches verified files for later use. Each circuit depth must be downloaded once; cached artifacts are checked again before use. The manifest records hashes observed from the same upstream host, not an independently signed provenance statement. The contract tests and Sepolia smoke script use the same manifest and an independently checked local cache at `cache/zkcg-proving`; set `ZKCG_PROOF_CACHE` to use another location. A cached file with the wrong hash fails closed. It uses a verifier double only for separate policy-boundary tests.

With a fresh local deployment and database running, set `TEST_GATE_ADDRESS` to the deployed gate and run `npm run test:local-chain` to exercise issuer approval and revocation on the real local contracts. This adds and revokes a synthetic identity in that group.

For the local browser smoke test, install a Playwright Chromium browser with `npx playwright install chromium`, start PostgreSQL, a fresh Hardhat node, deploy with `npm run deploy:local`, start the issuer service and Vite, then run `npm run test:browser`. With Vite running, `npm run test:artifacts` checks artifact tampering and cached proof generation; `npm run test:artifacts:node` covers the Node cache. The test uses the default local deployment address, Hardhat account 0 as the issuer sign-in wallet and account 1 as the participant. Allowlist the issuer address and use only disposable local accounts. It removes its own synthetic database records after a successful run and changes the local group. On failure it preserves those records and prints the synthetic reference for investigation; if the recovery test detached a transaction hash, it also prints that hash.

The issuer endpoint tracks operations as preparing, pending, confirmed, failed or unknown. Reconcile pending transactions with `POST /api/admin/operations/:id/reconcile`. A preparing or unknown operation without a hash requires manual chain investigation; do not resubmit blindly. If the original transaction hash is found, attach it through the issuer console or `POST /api/admin/operations/:id/attach` with `{ "txHash": "0x…" }`. The service checks sender, contract, action and commitment before attaching; reconcile the receipt afterward. If no matching hash can be found, the operation remains unresolved. The loopback demo API authenticates wallet signatures with short-lived challenges and enforces issuer and participant roles server-side. Sessions expire after eight hours and are kept in browser memory; signing out or reloading requires signing in again. The issuer sees the participant sign-in address and application. Public audit does not require sign-in. This prototype is not hardened for public deployment. See [ARCHITECTURE.md](ARCHITECTURE.md) for intended boundaries and [docs/VALIDATION.md](docs/VALIDATION.md) for local evidence and remaining checks; [docs/TECHNICAL-REPORT-IEEE.tex](docs/TECHNICAL-REPORT-IEEE.tex) and its [PDF](docs/TECHNICAL-REPORT-IEEE.pdf) use the IEEEtran conference class. The earlier Markdown draft and browser-rendered approximation are retained for comparison.

To create an encrypted keystore from an issuer key already loaded in `ISSUER_PRIVATE_KEY`, run `npm run keystore:create -- deployments/issuer.keystore.json` in an interactive terminal. The command prompts twice without displaying the passphrase, requires at least 12 characters, and refuses to overwrite an existing file. It does not alter the original key or the running service. The issuer can use an encrypted JSON keystore instead of a plaintext private-key environment variable: set `ISSUER_KEYSTORE_PATH` and `ISSUER_KEYSTORE_PASSWORD`, and leave `ISSUER_PRIVATE_KEY` unset. Keep the keystore file and password outside source control, restrict filesystem access, and supply the password through a protected local environment. The process still holds the decrypted key in memory; this is not a hardware signer or production key-management system.

The issuer binds an empty database to the chain ID, gate, Semaphore group and group-creation block. Restarting a temporary Hardhat node creates a new chain, so use a new empty PostgreSQL database or schema for its deployment; the service refuses to attach old or unbound populated records. Preserve old data for investigation instead of repointing it. The sample compose credentials and loopback services are for local development only.

`npm audit --omit=dev` still reports advisories in the pinned Semaphore/SNARK dependency tree. Review those dependencies before any deployment beyond a disposable local prototype.

## Sepolia deployment

The editable [demo presentation](docs/DEMO-PRESENTATION.pptx) and its [PDF preview](docs/DEMO-PRESENTATION.pdf) summarize the architecture, demonstration sequence, measured evidence and limitations. The recorded Sepolia contract deployment and testnet application validation are described in [docs/VALIDATION.md](docs/VALIDATION.md). A separate new deployment requires a funded testnet deployer, Sepolia RPC and explicit deployment authorization. Set `SEPOLIA_RPC_URL` and `DEPLOYER_PRIVATE_KEY` in the shell, then, only when authorized, set `CONFIRM_SEPOLIA_DEPLOYMENT=yes` and run `npm run deploy:sepolia`. The script creates `deployments/sepolia.jsonl` exclusively and records each step and receipt. If it stops, inspect the journal and chain before any retry; it refuses to overwrite the journal. Save the printed addresses, chain ID, group ID and creation block. Configure the issuer with a separate empty database, `RPC_URL`, `GATE_ADDRESS`, the authorized issuer key and `SEMAPHORE_START_BLOCK` equal to the printed creation block. Configure the frontend build with `VITE_CHAIN_ID=11155111`, `VITE_START_BLOCK` set to that block, and `VITE_RPC_URL` set to a public read-only RPC URL for the audit view. Never embed a private RPC credential in frontend configuration. For Sourcify source verification, preserve `deployments/sepolia.jsonl` and the original build artifacts, then run `npm run verify:sepolia`. The script uses Sourcify API v2, records verification tickets, and checks for exact matches. Explorer verification is a separate result. For a testnet smoke test, set `GATE_ADDRESS`, `SEMAPHORE_START_BLOCK`, and `CONFIRM_SEPOLIA_SMOKE=yes`, then run `npm run smoke:sepolia` with the authorized issuer key configured as `DEPLOYER_PRIVATE_KEY`. It funds a dedicated test participant, adds a synthetic identity, registers that participant, checks replay and stale-root rejection, and revokes the test identity. The participant key is saved with restricted permissions in the ignored deployments directory; the remaining test ETH, if any, stays there. It creates `deployments/sepolia-smoke.jsonl` exclusively; if interrupted, inspect the journal and chain before any retry. Verify contracts separately; local tests do not prove testnet behavior. Do not expose keys in frontend variables.
